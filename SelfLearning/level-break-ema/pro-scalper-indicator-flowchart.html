Pro Scalper Approximation — Indicator: Signals, Timing, Exits & Stops

Logic map for the indicator() conversion. Same Kalman-SuperTrend engine and ADX Volatility Wave zones as the strategy, but strategy orders are replaced by a virtual-position state machine, and a new Signal Timing layer addresses the "one candle lag": Confirmed vs Real-time flags plus anticipatory early-warning diamonds.

1 · End-to-End Overview (Indicator)

Bar data → engine recomputes trend + waves → the timing gate decides when a flip becomes a flag → virtual position opens → four exit conditions manage it → alerts fire (no orders placed).

2 · Signal Timing — the "lag vs. lead" lever NEW

This is the layer added in the indicator. It decides when a SuperTrend flip is allowed to become a visible flag, and adds an anticipatory pre-signal that leads the confirmed flip.

flowchart TD
    FLIP[SuperTrend trend
state changed this bar] --> MODE{Flag timing
mode}
    MODE -- "Confirmed (no repaint)" --> CB{"barstate.isconfirmed?
(bar closed)"}
    MODE -- "Real-time (leading)" --> RT["Fire NOW on the
developing candle"]
    CB -- Yes --> FIRE([Flag fires at close
~1 bar late · stable])
    CB -- No --> WAIT[Wait for bar to close]
    RT --> RTF([Flag fires intrabar
LEADS · may REPAINT])

    PRICE[Current close] --> NEAR{"Within
warnAtrMult × ATR
of opposite band?"}
    NEAR -- "uptrend & near upBand" --> WS([◆ Early SELL warning])
    NEAR -- "downtrend & near dnBand" --> WL([◆ Early BUY warning])
    NEAR -- "no" --> NN[No warning]

    classDef ok fill:#0e2430,stroke:#39c5cf,color:#e6edf3;
    classDef repaint fill:#2a2411,stroke:#d29922,color:#e6edf3;
    class FIRE ok;
    class RTF repaint;
    class WS,WL repaint;
Mode / SignalWhen it appearsRepaints?Use for
Confirmed (default) At bar close, once the flip is locked (barstate.isconfirmed) No Backtest-accurate signals; matches the 89.2% fit
Real-time Intrabar, on the developing candle the moment state flips Yes Discretionary early heads-up (accept it may vanish)
◆ Early-warning When price gets within warnAtrMult × ATR of the flip band No* Anticipation — "a flip is getting close"
The honest tradeoff: you cannot be both earlier and guaranteed correct — that needs future data. Confirmed is stable but ~1 bar late. Real-time leads but can appear then disappear before the candle closes. Early-warning is a proximity alert (not every warning becomes a flip). *The warning bar itself doesn't repaint, but proximity can come and go as price moves.

Reduce raw lag too

Lower Kalman R and/or ATR Period makes the bands react sooner (less smoothing lag) — at the cost of more whipsaw / false flips.

Warning throttle

Only the first bar of a fresh proximity fires a diamond (not warnFlip[1]), so you don't get a solid wall of warnings while price hugs the band.

Still session-gated

Both flags and warnings respect the RTH 0930–1600 filter — nothing fires outside session.

Unchanged engine: signals come only from a SuperTrend trend-state flip, now passed through the timing gate above. Wave zones never create entries.

4 · Virtual Position State Machine replaces strategy orders

An indicator can't place orders, so posState (1 long / −1 short / 0 flat) is tracked by hand. It drives the entry/stop/target lines, TP markers, and exit alerts exactly like the strategy's real position did.

flowchart TD
    ST0["posState = 0 (flat)"] --> SIG{New signal?}
    SIG -- BUY --> L["posState = +1
store entryPrice, entryAtr,
entryBar · beTriggered=false"]
    SIG -- SELL --> S["posState = −1
store entry vars · reset BE"]
    SIG -- none --> HOLD[Hold current state]
    L --> MGR[Exit manager runs each bar]
    S --> MGR
    HOLD --> MGR
    MGR -- "any exit hits" --> FLAT["posState = 0
reset beTriggered
fire exit alert"]
    MGR -- "opposite signal" --> REV[Reverse: open other side]
    FLAT --> ST0

    class FLAT ex;

5 · Exit Logic — Four Independent Conditions

Once posState ≠ 0, whichever fires first flattens the virtual position and sends an exit alert. Same four rules as the strategy.

6 · Stop Management & Breakeven ("Trailing")

Same as the strategy: not a continuous trail — a one-time breakeven jump. After a 1×ATR favorable move, the stop snaps to entry and stays.

flowchart TD
    E[Virtual trade opens] --> INIT["Stop = entry ∓ 1.5×ATR
beTriggered = false"]
    INIT --> W{Favorable move
≥ 1.0×ATR?}
    W -- No --> W
    W -- "Yes" --> BE["beTriggered = true
Stop JUMPS to entry"]
    BE --> LOCK["Stop stays at breakeven
(does NOT keep trailing)"]
    LOCK --> DONE{Stop or target
eventually hit}
    DONE --> OUT([Flat + exit alert])

    classDef be fill:#2a2411,stroke:#d29922,color:#e6edf3;
    class BE,LOCK be;
On chart: grey = Entry Price, red = live Stop Loss (snaps up to grey on breakeven), green = fixed Take Profit. On-open SL / TP labels print the initial bracket. Because there's no order engine, these are drawn from the virtual position for visual/alert use only.

7 · ADX Volatility Wave Zones (Exit Reference Only)

Unchanged from the strategy. Red (upper) / green (lower) gradient ribbons are overbought/oversold zones feeding the zone-touch exit and TP markers — never entries.

Indicator port of an original approximation script (not a copy of any protected indicator), for research/comparison. Only Confirmed timing is non-repainting and matches the ~89% entry fit; Real-time leads but repaints; early-warning is a proximity alert, not a guaranteed flip. Indicators place no orders — the virtual position exists only to draw levels and fire alerts. Not financial advice; past/hypothetical behavior is not indicative of future results.
